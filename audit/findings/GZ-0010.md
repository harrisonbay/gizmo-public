# GZ-0010: force tree applies the top-tree capacity to ordinary nodes

- Status: fixed
- Confidence: high
- Affected configuration: restart-0 tree construction, especially sparse or
  strongly nonuniform particle layouts
- Oracle: public differential-mass shock-tube restart (regression)

## Evidence

`force_create_empty_nodes()` allocates ordinary internal nodes from `Nodes`,
whose allocation and indexing limit is `MaxNodes`. The abort guard also
compared that ordinary-node count with `MaxTopNodes`, which instead sizes the
separate domain-decomposition `TopNodes` array. The two capacities are
independent.

The public `shocktube_ics_diffmass.hdf5` deterministically reaches the smaller
unrelated `MaxTopNodes` threshold during restart-0 and aborts even though its
`Nodes` allocation still has capacity. Removing only that second comparison
allows the same one-rank run to construct the tree and complete.

The corrected run used the byte-pinned public IC
`46d8cc58a167ae772b29d2ed3423bad03a3853816fa64af4327b07eb7fad9f72`,
evolved all 512 particles for 8,192 synchronized steps, and wrote all 11
scheduled outputs through `t=5`. Its initial and terminal raw snapshot digests
are `5c9668162d8788bdcaacc1eb9eafdcd5342f1340e32ac252e46cbe89641cf3ad`
and `6aead3d11ac384af80591c9c22361e011c861d3ec154c21b7f07c304d6bc39b1`;
reduced state tables and complete provenance are pinned in
`validation/oracles/shocktube/diffmass-evolution-manifest.json`.

Pinned source: [incorrect mixed-capacity guard](https://github.com/pfhopkins/gizmo-public/blob/a828c4ba79d67093bd1a3d04f6f90b5d2d94d65f/gravity/forcetree.c#L350-L402).

## Fix

Guard the ordinary-node allocation only with `MaxNodes`. `TopNodes` is already
bounded while the domain top tree is built and must not constrain this separate
array.

## Impact

Valid public initial conditions can abort before their first force evaluation,
with behavior depending on unrelated domain top-tree allocation heuristics.
Increasing `TopNodeAllocFactor` can mask the defect but does not make the guard
semantically valid.
